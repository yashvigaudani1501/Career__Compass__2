# 🚀 ATS Tracker - Node.js Backend Documentation

## 📌 Overview
The Backend serves as the main traffic controller for the ATS Tracker platform. Built with **Node.js, Express, and MongoDB**, it handles User Authentication, Role-Based Access Control (RBAC), Database CRUD operations, File Uploads (PDFs), and acts as a proxy to communicate with the Django ML Microservice.

## 🛠 Tech Stack
- **Framework:** Node.js with Express.js
- **Database:** MongoDB Atlas (accessed via Mongoose ODM)
- **Authentication:** JSON Web Tokens (JWT) & bcryptjs
- **File Handling:** Multer (for PDF resume uploads)
- **Microservice HTTP Client:** Axios
- **Form Data Handling:** form-data (to proxy files to Django)

## 🗄️ Database Schemas (MongoDB)

### 1. User (`users`)
Handles authentication for *all* roles. Contains basic profile fields for standard users.
- `name`, `email`, `password` (hashed)
- `role`: Enum `['USER', 'COMPANY', 'ADMIN']`
- `profession`, `skills`, `description`, `profileImage`

### 2. CompanyProfile (`companyprofiles`)
Dedicated data for companies. Links to a `User` via `userId`.
- `companyName`, `work`, `location`, `companyInfo`

### 3. UserResume (`userresumes`)
Stores the user's uploaded resume and the data generated by the ML service.
- `userId` (Ref: User)
- `resumePath` (String, path to PDF)
- `atsScore` (Number, 0-100)
- `extractedSkills` (Array of Strings)
- `aiSuggestedJobs` (Array of Strings)

### 4. Job (`jobs`)
- `company` (Ref: User)
- `title`, `description`, `requiredSkills`, `location`, `salary`, `experienceLevel`, `isActive`

### 5. JobApplication (`jobapplications`)
The nexus connecting a user to a job using their AI-analyzed resume.
- `job` (Ref: Job)
- `applicant` (Ref: User)
- `resumeData` (Ref: UserResume)
- `status`: Enum `['Pending', 'Reviewed', 'Accepted', 'Rejected']`

## 📡 API Endpoints

### 🟢 1. Authentication Routes (Public)
| Method | Endpoint | Description | Body |
|---|---|---|---|
| `POST` | `/api/auth/register` | Registers a normal USER. | `{ name, email, password }` |
| `POST` | `/api/auth/login` | Authenticates ANY role, returns JWT. | `{ email, password }` |

### 🔴 2. Admin Routes (Protected: `ADMIN`)
| Method | Endpoint | Description | Body |
|---|---|---|---|
| `POST` | `/api/admin/create-company` | Creates Company auth + Triggers Django scraper if `website` is provided. | `{ name, email, password, location, website }` |

### 🟠 3. Company Routes (Protected: `COMPANY`)
| Method | Endpoint | Description | Body |
|---|---|---|---|
| `POST` | `/api/company/post-job` | Posts a new job listing. | `{ title, description, requiredSkills, location, salary, experienceLevel }` |
| `GET` | `/api/company/applicants/:jobId` | View all applicants for a job, deeply populated with User Info and AI ATS Scores. Sorted by highest score. | None |

### 🔵 4. User Routes (Protected: `USER`)
| Method | Endpoint | Description | Body / Format |
|---|---|---|---|
| `PUT` | `/api/user/profile` | Update profile details. | `{ profession, skills, description, profileImage }` |
| `GET` | `/api/user/jobs` | Fetch all active jobs in the system. | None |
| `POST` | `/api/user/upload-resume` | Upload PDF. Triggers Django ML to analyze and returns AI results. | `multipart/form-data` -> `resume: [FILE]` |
| `POST` | `/api/user/apply/:jobId` | Apply to a job. Fails if no ML-analyzed resume exists. | None |

### 🩺 5. System Routes (Public)
| Method | Endpoint | Description | Body |
|---|---|---|---|
| `GET` | `/api/health` | Health check to verify Node.js and DB status. | None |

## 🤖 Microservice Communication Logic
The Node.js backend acts as a proxy to the Django ML service using `axios`.

1. **Resume Analysis (`/upload-resume`):**
   - Node receives PDF via Multer and saves it to `/uploads`.
   - Node uses `form-data` and `fs.createReadStream` to POST the file to Django (`/api/process-resume/`).
   - Django returns `ats_score`, `extracted_skills`, and `suggested_jobs`.
   - Node saves this to `UserResume` in MongoDB and responds to the frontend.

2. **Company Scraping (`/create-company`):**
   - If Admin provides a `website` URL, Node makes a POST request to Django (`/api/scrape-company/`).
   - Django scrapes the site, Groq AI summarizes it, and returns `work` and `companyInfo`.
   - Node saves this directly to the `CompanyProfile` collection.
